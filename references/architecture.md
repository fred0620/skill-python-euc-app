# 架構與原因

## 適用情境

業務端的人用 Python（常常搭配 AI）做出小工具，要給同事在自己的 Windows 電腦上用。工具不會進 production、不連公司核心系統，但會碰到業務資料。這類工具的風險通常不在程式碼，而在：

- 只有作者懂，作者離開就沒人能維護（bus factor）。
- 每個人電腦上的版本不同，出錯時查不出是哪一版。
- 資料散落在程式資料夾裡，更新時被覆蓋或被一起分享出去。

架構的每個決定都在處理這三件事。

## 資料夾分三塊

```text
my-tool/
  run.bat       入口，只有一行
  app/          程式，換版時整包換掉
  workspace/    使用者資料，第一次啟動時建立，換版不動
  runtime/      uv、Python、套件，自動建立，可刪掉重建
```

- **為什麼分開**：換版只要「把 app 換掉」，不用判斷哪些檔案是使用者的。備份或搬電腦只要複製 `workspace`。
- **為什麼 `workspace` 不在發布包裡**：發布包永遠不可能帶出任何人的資料，也不會覆蓋別人的資料。
- **為什麼 `runtime` 在工具資料夾內**：不動系統 Python、不改 PATH，刪掉整個資料夾就完全移除。資料夾搬家後 venv 會失效，啟動程式偵測到就自動重建。
- **路徑集中在 `paths.py`**：啟動程式設定 `APP_HOME` 指向最外層；沒設定時（開發、測試）用 `app/` 的上一層。程式其他地方不准自己組路徑。
- **起始資料**：放在 `app/examples/workspace/`，只在第一次建立 `workspace` 時複製一次。使用者刪掉的東西不會在下次啟動時又出現。

## 啟動程式

`run.bat` → `app/launcher.ps1`：

1. 沒有指令（雙擊）時，找工具資料夾裡比目前新的 `<slug>-x.y.z.zip`，問要不要換版。
2. 確認 `runtime/` 裡有 uv（下載時驗證 SHA256）、Python 與套件。
3. 執行 `python -m <package>`。

細節：

- **指令列模式不檢查更新、不暫停**：`run.bat run ...` 這類批次指令要能放進排程，不能停下來等人按鍵。只有雙擊開啟時，出錯才會停在「按 Enter 關閉」。
- **離線套件**：發布包附 Windows 64 位元的 wheel（`app/wheels`），用 `uv pip sync --no-index --find-links` 安裝。`sync` 會讓環境和清單完全一致，舊版多出的套件會被移除。使用者不需要連到 PyPI，只有第一次要從 GitHub 下載 uv 和 Python。
- **為什麼不用 `uv sync --frozen` 裝離線套件**：它不吃 `--find-links`。開發時沒有 `app/wheels`，才用 `uv sync --frozen`。
- **為什麼用 `-ExecutionPolicy Bypass`**：沒有程式碼簽章的腳本，在預設原則下無法執行。公司要求簽章時，請 IT 簽 `launcher.ps1`，不要教使用者改系統設定。

## 換版

使用者流程：從 GitLab Release 下載 ZIP，不解壓，放進工具資料夾，雙擊 `run.bat`，按 Enter。

`launcher.ps1` 的安裝順序：

1. 解壓到 `updates/`，找到裡面的 `app/`，確認版本和檔名一致。
2. 刪掉舊的 `app.old`，把目前的 `app` 改名為 `app.old`（防毒鎖住時重試）。
3. 把新的 `app` 移進來；失敗就把 `app.old` 改回 `app`。
4. 覆蓋 `run.bat`、`run.sh`，刪掉 `updates/` 和 ZIP。
5. 換成由新版的 `launcher.ps1` 繼續（新版可能有新的套件要裝）。

`run.bat rollback` 把 `app` 和 `app.old` 互換，再執行一次就換回來。

刻意不做的事：

- **不連網自動檢查**：使用者電腦通常連不到要登入的 GitLab，也沒有共用位置可放版本資訊；做了反而常常失敗。改成把手動步驟寫清楚、附圖解。
- **不做全面回滾**：啟動程式只會往新版換。要所有人回到舊行為，就發一個 revert 的新版本。
- **不讓使用者把新資料夾整個覆蓋舊的**：舊版的檔案會殘留，換版說明裡明確寫出來。

## 不包成 exe

- PyInstaller 產生的 exe 常被防毒誤判（打包工具常被惡意程式濫用，部分引擎有專門的特徵碼），簽章也不一定能解決。
- 每次啟動要解壓到暫存，慢，而且不能只換一部分。
- 資料夾加腳本比較透明，IT 看得懂、容易審核。
- 真正讓程式「可信」的是簽章與受控的發布來源，不是 exe 這個格式。

## 本機網頁介面

- Flask 只綁 127.0.0.1，瀏覽器當介面。使用者熟悉，不用裝任何東西。
- 前端只用系統字型和純 CSS／JS，不載入外部資源。
- 頁面每 15 秒送 heartbeat，全部關閉後程式自動結束；有背景工作時等工作完成。電腦睡眠醒來不會誤判。
- 已開著時再啟動，用 `/api/ping` 加上資料夾路徑的雜湊判斷是不是同一份工具，只開啟原本的頁面。
- 查本機服務時不走系統 Proxy（公司電腦常設 `HTTP_PROXY`，會讓 127.0.0.1 的檢查失敗）。

## 版本號

- 只寫在 `app/pyproject.toml`。Python 程式用正則讀（不依賴套件安裝），啟動程式用 `Select-String` 讀，CI 比對標籤。
- 畫面左上角顯示版本號，使用者回報問題時直接看得到。
